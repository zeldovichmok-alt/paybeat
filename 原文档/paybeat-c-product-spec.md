# PAYBEAT C 端产品设计

## 产品定位

PAYBEAT 是一个把工作时间换算成实时收入的个人计费工具。用户先填写自己的收入口径和工作安排，再开始当天计费；页面用大号金额和秒级计时呈现“工资正在增长”的反馈。

首版允许游客直接使用，规则和日结记录保存在本机。登录、云端同步、多个工作档案和跨设备同步放到后续版本。

## 首次使用流程

1. **欢迎**
   - 标题：工资跳动
   - 品牌：PAYBEAT
   - 说明：每一秒都按你的工作规则计算。
   - 主按钮：开始设置

2. **收入设置**
   - 收入类型：首版月薪；后续增加时薪、日薪、年薪。
   - 金额：必填，必须大于 0。
   - 货币：人民币、美元、欧元、英镑。
   - 收入口径：首版先保存字段，后续增加税前、到手和扣款估算。

3. **工作安排**
   - 工作日：周一至周日多选。
   - 上班时间、下班时间。
   - 午休开始、午休结束。
   - 自动开始：打开后，在选中的工作日到上班时间自动计费。
   - 实时预览：每天计费时长、每秒单价、选中的工作日数量。

4. **确认并开始**
   - 保存规则快照。
   - 当前是工作日且在工作时段内时，立即开始今天的计费。
   - 非工作日显示“今天不上班”，用户可以在规则中临时选择当天工作。

## Today 主界面

- 顶部显示 PAYBEAT、当前状态和规则编辑入口。
- 主视觉显示今日累计收入和有效计时。
- 次级信息显示每秒单价、本月工作日、今日工作时段。
- 主按钮按状态变化：
  - 未设置：先完成设置
  - 已设置：开始今天
  - 计费中：暂停今天
  - 已暂停：继续今天
  - 已结算：今日已结算
- 结束并结算会冻结今日金额，并写入历史。
- 午休按规则自动暂停计费，恢复后继续累计有效工作时间。

## 规则编辑

- 计时中锁定收入和时间规则，避免当天金额被中途改写。
- 暂停后可以编辑；首版保存后重新开始当天计费。
- 下一版改为“明天生效”，当天使用规则快照，历史不会被未来设置重算。
- 输入错误在表单内提示：金额必须大于 0；至少选择一个工作日；上下班和午休时间不能重叠或倒置。

## 数据结构

```js
{
  profileComplete: true,
  monthlySalary: "11200",
  currency: "¥",
  monthKey: "2026-10",
  workdays: [1, 2, 3, 4, 5],
  workStart: "09:00",
  workEnd: "18:30",
  breakStart: "12:00",
  breakEnd: "13:30",
  autoStart: true
}
```

计费只保存开始、暂停、继续和结束等时间点，每秒显示时重新计算有效工作区间。每日结算记录应保存当日规则快照，避免编辑月薪后改变历史金额。

## 版本节奏

### MVP

- 单个工作档案
- 月薪、货币、自定义工作日、上下班和午休
- 手动开始、暂停、继续、结束
- 工作日自动开始和结束
- 今日金额、每秒单价、历史日结
- 本机保存和手机局域网访问

### V1

- 时薪、日薪、年薪
- 多个工作档案：全职、兼职、自由职业
- 明天生效的规则版本
- 税前/到手口径
- 社保、公积金、个税估算，并明确标注“估算”
- 登录和云端同步

### V2

- 小程序适配
- 节假日和地区日历
- 轮班、跨午夜班次、多段休息
- iOS Widget、通知和后台提醒
- 海外地区、时区和本地化货币

## 平台策略

- **Web/PWA**：验证产品需求和视觉，支持手机浏览器添加到主屏幕。
- **微信小程序**：复用规则模型和计费核心，替换本地存储、通知和登录能力。
- **iOS 海外版**：复用规则模型，使用 SwiftUI 重做 Today、Rules、History 三个核心页面。

所有平台共用同一套规则计算逻辑；平台层只负责存储、提醒、登录和界面适配。
