# PAYBEAT 第一轮功能优化方案

版本：2026-10-22  
状态：第一轮已实现，进入验证与 UI 迭代准备  
适用范围：当前本地优先的按秒计费工具

## 1. 这轮要解决什么

当前版本只支持“月薪 + 工作日 + 上下班时间 + 一段午休”，所有有效工作时段使用同一个每秒单价。本轮先把收入和时间规则扩展成可配置模型，让用户能够更接近真实的工作安排：

- 选择不同币种，并保持金额、历史和显示格式一致。
- 配置社保和公积金，分别看到税前收入、个人扣款后估算和雇主成本。
- 记录午餐、短暂离岗和自定义休息时间，并决定是否计费。
- 配置工作日加班、周末加班和节假日加班倍率。
- 保持数据只存在用户自己的设备，不引入账号、云同步或第三方汇率服务。

本轮的目标是把计算口径设计清楚，给下一次 UI 迭代提供完整字段和状态。功能先写入数据模型和计算层，等方案确认后再改界面。

## 2. 设计原则

### 2.1 真实扣款与估算分开

社保、公积金的实际扣款受到地区、年度、缴费基数上下限和公司政策影响。PayBeat 只提供用户可编辑的估算，不把任何城市的比例写死，也不把估算结果描述成工资单或申报结果。


### 2.2 工作时间和计费时间分开

“人在工作时段内”不等于“这一秒一定按正常单价计费”。每个时间段都应有自己的标签和计费状态：

- 工作：计费。
- 午餐：默认不计费，可配置为带薪休息。
- 短暂离岗：默认不计费，可设置每日额度或手动结束。
- 摸鱼/个人休息：默认不计费，作为可选的自定义标签。
- 加班：计费，但使用加班倍率。


### 2.3 先支持用户自定义，再接地区模板

第一轮允许用户直接输入基数、比例和倍率。地区模板、节假日历法和自动更新规则留到后续版本，避免把不确定的政策数据伪装成系统事实。

### 2.4 不接入实时汇率

币种选择只改变金额的货币单位和显示格式，不自动把人民币换算成美元或其他币种。跨币种换算需要汇率来源、更新时间和误差提示，暂不放进第一轮。

## 3. 功能一：不同币种

### 3.1 第一轮支持

建议支持以下币种：

| 代码 | 展示 | 小数位 |
| --- | --- | ---: |
| CNY | ¥ 人民币 | 2 |
| USD | $ 美元 | 2 |
| EUR | € 欧元 | 2 |
| GBP | £ 英镑 | 2 |
| JPY | ¥ 日元 | 0 |
| HKD | HK$ 港币 | 2 |
| SGD | S$ 新加坡元 | 2 |
| AUD | A$ 澳元 | 2 |

内部同时保存 `currencyCode` 和 `currencySymbol`，不要只保存符号，因为 `¥` 可能代表人民币、日元或其他货币。

### 3.2 规则

- 一个工作档案只使用一种币种。
- 修改币种只影响之后的新规则和新结算记录；已结算历史保留原币种。
- 金额输入允许两位小数；日元默认不显示小数。
- 所有金额计算使用最小货币单位或高精度数值，最后一步再按币种格式化，避免每秒累计产生浮点误差。
- 第一轮不做汇率转换，不显示“约合人民币”。

### 3.3 待确认

是否需要同时保留“币种代码 + 符号”，例如显示为 `USD 12.34`，以避免只看 `$` 时不清楚是哪一种美元。

## 4. 功能二：社保与公积金

### 4.1 展示口径

主收入仍然是用户配置的月薪。若开启扣款估算，页面可提供三种口径：

1. **税前月薪 / Gross**：用户输入的月薪。
2. **个人扣款后估算 / Estimated net**：税前月薪减个人社保、公积金和可选的税费估算。
3. **雇主成本 / Employer cost**：税前月薪加雇主承担的社保和公积金。

本轮只实现社保和公积金；个税可预留字段，默认关闭。

### 4.2 社保项目

默认拆分为五险：

- 养老保险
- 医疗保险
- 失业保险
- 工伤保险
- 生育保险

每一项都可单独开启或关闭。对个人和雇主分别保存比例或固定金额。

### 4.3 公积金项目

公积金单独配置：

- 是否启用。
- 个人比例。
- 雇主比例。
- 缴费基数。
- 最低基数和最高基数。
- 是否使用固定金额替代比例。

### 4.4 基数规则

建议提供三种基数方式：

- `salary`：按月薪作为基数。
- `custom`：用户输入基数。
- `capped_salary`：按月薪计算，但自动应用最低和最高基数。

计算顺序：

```text
缴费基数 = max(minBase, min(maxBase, baseValue))
个人项目扣款 = 缴费基数 × employeeRate + employeeFixed
雇主项目成本 = 缴费基数 × employerRate + employerFixed
```

如果用户只填写比例而没有填写基数，保存时必须提示并要求补全；不能默认为零。

### 4.5 实时显示方式

社保和公积金本质上按月缴纳，不适合被伪装成每秒真实扣款。建议分成两个值：

- 实时卡继续显示“今日税前收入”和“今日收入估算”。
- 月度摘要显示“本月预计个人社保”“本月预计公积金”“本月扣款后估算”“本月雇主成本”。
- 如需要每秒对照，可显示“按计划工时摊销的每秒扣款估算”，并标注“估算”，不写入真实扣款流水。

```text
个人社保月估算 = 各社保项目个人扣款之和
个人公积金月估算 = 缴费基数 × employeeRate + employeeFixed
扣款后月估算 = 税前月薪 - 个人社保月估算 - 个人公积金月估算 - 可选税费
雇主月成本 = 税前月薪 + 雇主社保月估算 + 雇主公积金月估算
```

### 4.6 合规文案

设置页面和月度摘要必须出现：

> 社保、公积金和到手金额仅供估算，实际金额以公司工资单和当地政策为准。

## 5. 功能三：午餐、短暂离岗和摸鱼时间

### 5.1 统一时间段模型

不再只保存 `breakStart` 和 `breakEnd` 两个字段，改为一个可扩展的时间段数组：

```ts
TimeSegment {
  id: string
  label: 'work' | 'lunch' | 'short_break' | 'personal' | 'overtime' | 'custom'
  name?: string
  start: 'HH:mm'
  end: 'HH:mm'
  billable: boolean
  paidRate: 'normal' | 'zero' | 'custom'
  multiplier?: number
}
```

已有午休迁移为：

```json
{
  "label": "lunch",
  "name": "午餐",
  "start": "12:00",
  "end": "13:30",
  "billable": false,
  "paidRate": "zero"
}
```

### 5.2 建议的用户命名

代码和数据模型可以支持“拉屎”“摸鱼”等自定义名称，但正式 UI 默认使用中性名称：

- `午餐休息`
- `短暂离岗`
- `个人休息`
- `自定义休息`

用户可以在备注里写“洗手间”“接水”“抽烟”或“摸鱼”，这些标签只保存在自己的设备中。

### 5.3 第一轮的三类休息

| 类型 | 默认是否计费 | 建议能力 |
| --- | --- | --- |
| 午餐 | 否 | 固定时段，可设置为带薪 |
| 短暂离岗 | 否 | 手动开始/结束；可设置每日总额度 |
| 个人休息/摸鱼 | 否 | 手动开始/结束；可查看当天累计时长 |

“短暂离岗”是否计费不能由系统替用户判断；用户可以配置为 `billable: true`，此时按正常单价计费，但仍记录该段标签。

### 5.4 额度和超时

建议第一轮提供可选的每日额度：

- 不限制。
- 15 分钟。
- 30 分钟。
- 自定义分钟数。

额度只用于提醒和统计，不自动扣钱。超过额度后：

- 默认继续按“不计费”处理。
- 页面提示“今日短暂离岗已超过设置额度”。
- 用户仍可手动结束离岗并恢复计费。

这样可以避免用户误触后被系统自动扣除过多收入。

### 5.5 时间段边界

- 时间段不能重叠。
- 同一标签可以有多段记录。
- 允许跨午夜，但第一轮只在数据模型预留，界面暂不开放复杂跨日编辑。
- 计时状态只能有一个活动段。
- 从工作切换到离岗时保存事件；恢复工作时再保存事件，不每秒写记录。

## 6. 功能四：加班

### 6.1 支持场景

第一轮支持三类加班：

1. **工作日延时**：超过计划下班时间继续工作。
2. **休息日加班**：原本未选中的工作日手动开始加班。
3. **节假日/特殊日期加班**：先按自定义日期记录，节假日历法留到后续版本。

### 6.2 加班倍率

默认预设：

| 场景 | 默认倍率 | 备注 |
| --- | ---: | --- |
| 工作日延时 | 1.5× | 用户可改 |
| 休息日加班 | 2.0× | 用户可改 |
| 节假日加班 | 3.0× | 用户可改 |
| 自定义加班 | 自定义 | 支持 `0.1–5.0×` |

这里的默认值只是产品预设，不能作为法律或公司制度结论。设置页应允许关闭预设并手动填写。

### 6.3 计算方式

```text
正常时薪 = 月薪 ÷ 本月计划计费总小时
加班时薪 = 正常时薪 × 加班倍率
加班收入 = 加班实际计费小时 × 加班时薪
今日总收入 = 今日正常收入 + 今日加班收入
```

如果用户选择“固定月工时”或“时薪”，正常时薪直接使用对应口径，不再用月薪除计划工时。

### 6.4 加班开始方式

建议提供两种方式：

- 自动识别：工作日超过下班时间后进入加班状态。
- 手动开始：点击“开始加班”，用于休息日或特殊日期。

自动识别默认关闭，避免用户下班后忘记停止导致持续计费。开启后需要在设置中明确显示“下班后自动进入加班”。

### 6.5 加班结算

每段计时事件需要记录 `rateType` 和 `multiplier` 快照。用户之后修改加班倍率时，历史加班金额不能重算。

## 8. 计算优先级和冲突处理

同一时刻只能匹配一个计费段，优先级建议如下：

1. 手动暂停 / 结束。
2. 明确标记的不计费休息。
3. 加班段。
4. 正常工作段。
5. 非工作日空闲时间。

如果时间段发生重叠，保存时阻止提交并告诉用户具体冲突的两个时间段。不要静默选择其中一个。

如果用户在计费中修改规则：

- 当前已发生的时间保留原规则和原倍率。
- 新规则从下一个事件或下一个工作日生效，具体采用哪一种需要在 UI 中明确。
- 为了减少历史重算风险，建议第一轮采用“新规则从下一工作日生效”。

## 10. 原定实现顺序（已完成，供后续迭代追踪）

### 第一步：只改数据模型和计算核心

- 将午休迁移为 `segments`。
- 增加 `rateType`、`multiplier`、`currencyCode`。
- 保留旧数据迁移，不改页面视觉。
- 为正常工作、未计费休息、加班写计算用例。

### 第二步：加入币种和自定义休息

- 币种代码、符号和小数位。
- 午餐、短暂离岗、个人休息。
- 活动计时段切换。
- 每日离岗额度和提醒。

### 第三步：加入加班

- 工作日延时。
- 休息日手动加班。
- 倍率快照和日结拆分。

### 第四步：加入社保和公积金估算

- 基数、上下限、个人比例、雇主比例。
- 月度摘要和估算提示。
- 历史日结保存扣款规则快照。

## 11. 验收标准

- 用户选择美元后，今日金额、每秒单价、历史金额均显示美元，历史旧记录币种不变。
- 用户开启公积金后，系统能分别显示个人公积金和雇主公积金，未填写基数时不能保存。
- 午餐和个人休息默认不计费，结束休息后能继续正常计费。
- 短暂离岗额度只产生提醒，不会未经确认自动扣款。
- 工作日延时和休息日加班使用不同倍率，日结中能拆分正常收入和加班收入。
- 修改规则后，已结算日期不会被重新计算。
- 同一设备刷新页面后，当前用户自己的设置仍可保留；更换使用者点击“清除本机数据”后进入空白设置页。
- 所有社保、公积金、到手金额均标注“估算”，不声称为正式工资或申报结果。

## 12. 本轮暂不做

- 自动读取当地社保、公积金政策。
- 实时汇率和自动换算。
- 个税自动申报或工资单替代。
- 后台持续运行的隐形计时。
- 多人账号、云同步和跨设备共享。
- 复杂轮班、跨午夜多段班次的完整 UI。

## 13. 第一轮已采用的产品决策

1. 社保、公积金放在设置里的高级区域，默认关闭；开启后可使用汇总比例或五险/公积金逐项配置。
2. 短暂离岗和个人休息默认不计费，同时提供带薪开关；额度只提醒，不自动扣款。
3. 加班预设倍率采用 `1.5× / 2× / 3×`，并允许用户覆盖到 `0.1–5.0×`。
4. 第一轮只做币种标记和格式化，不做实时汇率或人民币换算。
5. 计费中修改规则保留当天已发生的原规则；新规则从下一个工作日生效，页面显示生效日期。

## 14. 第一轮实现状态（2026-10-22）

上一轮功能已接入三个 HTML 页面；本轮仅更新经典主工具 index.html 与 pay-by-second.html，Readymag 继续保留独立视觉样式：

- 币种：CNY、USD、EUR、GBP、JPY、HKD、SGD、AUD；金额和历史同时保存币种代码与符号。
